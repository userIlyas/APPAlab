# Ограничения первой версии

Это снимок существующего решения, а не исправленная интеграция. Ничего из перечисленного не исправлялось при публикации.

1. **Чистый rebuild и полный `/v1/chat` — UNVERIFIED.** При подготовке не поднимался второй полный стек и не пересобирался Rust wheel; нет нового доказательства воспроизводимости всей системы. Проверены исходники/Compose и offline-поведение ранее собранного native wheel.
2. **APPA-контейнер остановлен.** На момент инвентаризации 2026-11-24 — exited, код 255. Причина не исследовалась по runtime-логам; новый успешный старт не подтверждён. Основной стек работает, но не содержит enforcement.
3. **Search namespace mismatch (подтверждено кодом).** `MCPClient` формирует `search.news_search`/`search.text_search`, а политика объявляет `search.news`/`search.text`. Тесты обходят настоящий MCP. Живой эффект — UNVERIFIED; не заявляем, что реальный поиск успешно понижает Trust.
4. **Embedding-зависимость.** В inspect переменная `EMBEDDING_API_KEY` пуста у memory-service и memory-orchestrator. Исторический отчёт сообщает 503 памяти; это не перепроверено HTTP-вызовом в этой публикации. Нужен разрешённый локальный совместимый embedding endpoint; готового stub здесь нет. Непустой LLM-ключ не доказывает доступность провайдера.
5. **Неперсистентный taint и вытеснение.** Session использует временный SQLite; restart/multi-worker/replica не сохраняют общий taint. Python cache ограничен `APPA_TAINT_MAX_SESSIONS` (4096); вытеснение тоже забывает метку. Не доказана безопасность всех конкурентных последовательностей tool calls.
6. **Изоляция по conversation_id, а не identity/audience.** Audience и привязка к customer_id не реализованы этой политикой; банковская OAuth/RBAC-проверка остаётся отдельным механизмом. Per-conversation тест — не cross-tenant security test.
7. **Общий backend.** Отдельный APPA Compose разделяет Keycloak/ABS/память/обсервабилити с основным стеком. Диагностический endpoint при флаге `1` может создать настоящий ledger transfer даже без LLM. В этом Compose флаг жёстко установлен в `1`; не выставлять его в публичную сеть и не запускать исторические E2E на основном стенде.
8. **Не весь egress охвачен.** Финальный текст LLM и лабораторные/прямые API-пути не защищены универсальным DLP. Память считается недоверенной по metadata, а не по анализу всех текстов. Trusted bank read не гарантирует отсутствие недоверенного текста в данных.
9. **Консервативное сужение.** Один разрешённый untrusted ingress понижает весь диалог; operator review/sanitizer recovery в обвязку не включён. Enforce при деградации блокирует gated-вызовы; ошибки после executor не откатывают эффект.
10. **Dependency drift.** Python requirements — диапазоны, образы — mutable tags, maturin — диапазон; Cargo.lock есть, но исходный build-скрипт не использует `--locked`. Побитная воспроизводимость не гарантирована. Runtime dependency inventory — наблюдение, не lock-файл. Wheel, кэш Cargo, Docker layers и volumes не включены.
11. **Ограничения build-скрипта.** Он очищает глобальные `/tmp/appa-build`/`/tmp/appa-dist`, предполагает имя исходного каталога `OpenAPPA`, не подходит для параллельных сборок. Выполнять только на отдельном чистом хосте. x86_64/glibc wheel не подходит ARM/macOS/musl без новой сборки.
12. **Демонстрационные настройки.** Открытые demo-учётные данные, Keycloak start-dev, намеренно vulnerable MCP и лаборатории. Не использовать реальные API-ключи/PII/платежи. UI обращается к порту 8000, не 8009.

## После первой публикации (отдельная задача)

Согласовать исправление имён search и проверку реального MCP на mock-сервисе; чистую сборку с фиксированными зависимостями; локальный embedding/LLM fixture и безопасный полный E2E; затем persistence/eviction/identity isolation/concurrency, diagnostic gates и observability. Этот список — план, не реализованные возможности.
