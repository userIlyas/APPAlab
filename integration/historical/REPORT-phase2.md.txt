## 1. Устранение fail-open (приоритет 1) — выполнено

**Проблема:** при `APPA_TAINT_MODE=enforce` и отсутствии колеса `appa_agent_python`
(или ошибке загрузки) обёртка `TaintGate.active` возвращала `False`, и `run_tool`
просто выполнял инструмент (passthrough) — enforcement деградировал в открытый режим.

**Исправление** (`services/common/appa_taint.py`):
- Введён инвариант: в режиме `enforce` **любая** неготовность движка/политики/сессии
  либо ошибка движка → `TaintDenied` **до** выполнения инструмента (fail-closed).
- Точки fail-closed в `run_tool`: отсутствие `conversation_id`, `_engine_ready() == False`
  (движок не загружен ИЛИ политика не загружена), невозможность открыть сессию,
  неожиданная ошибка `check`/`report` (трансляция в `TaintDenied`).
- `_reload_policy` при ошибке парсинга/чтения политики оставляет `_policy_toml=None`
  (не «мягкий» контур) и лог `CRITICAL`; `_load_native` в enforce логирует `CRITICAL`.
- Режимы: `enforce` — fail-closed; `observe` — advisory passthrough (осознанно);
  `off` — passthrough без загрузки движка.
- Добавлен `TaintGate.status()` (mode, engine_available, engine_identity, policy_loaded,
  policy_tools, declared_narrowers, allowed_narrow, fail_closed, sessions) и вывод в `/health`.

**Проверка (14/14 тестов, `tests/test_appa_taint.py`):**
`test_enforce_fails_closed_when_engine_unavailable`, `..._when_policy_missing`,
`..._without_conversation_id` — sink не выполняется; `test_observe_passes_through_...`
и `test_off_mode_passes_through` — ожидаемый passthrough.

Дополнительное доказательство потока меток — лог контейнера `agentic-banking-appa-1`:

```
appa_taint deny tool=abs.create_transfer conv=e2e-taint-<…> reason=[appa] Blocked:
abs.create_transfer cannot run. Why: - trust is suspicious, below the required floor trusted
```

Это подтверждает: метка поступает из точки ingress в policy engine (`search.text` →
`suspicious`), и запрещённая финансовая операция блокируется **до** обращения к АБС.

### Что НЕ подтверждено E2E (честно, разделяю статусы)

Полный сценарий через `/v1/chat` (LLM-граф + поиск + память) в этом окружении
не проходит по **несвязанной с OpenAPPA** причине: у сервиса памяти отсутствует
`EMBEDDING_API_KEY` (в `.env` значение пустое), поэтому самый первый узел графа —
`memory.recall` (`POST /api/v1/context`) — возвращает 503 «Embedding-модель недоступна»,
и граф не доходит до вызова инструментов. Это ограничение стенда, а не интеграции:
основной `banking-agent` страдает тем же (в логах `memory-service` видны 503 на
`/api/v1/context`). Поэтому:
- E2E «метка → блокировка» выполнен на **реальном gated `skills.mcp` + реальном движке
  OpenAPPA + реальном АБС** через диагностический endpoint изолированного образа
  (`POST /v1/appa/e2e/transfer`, монтируется только при `APPA_TAINT_E2E_HARNESS=1`,
  иначе 404);
- ingress в E2E — **синтетическое** допущение через реальный gate (поиск/память вне сети
  недоступны); полноценный ingress `search.*`/`memory.untrusted`/`travel.plan` покрыт
  юнит-тестами на реальном движке (см. `REPORT.md`, итого 14 тестов).

## 5. Персистентность taint между перезапусками (приоритет 5) — исследование и предложение

**Факты (подтверждено кодом OpenAPPA):**
- `appa-agent-python/src/lib.rs:221,244,246` — хранилище `tempfile::tempdir()`,
  `Runtime::open(config, store.path().join("appa.db"), None)`, `TrajectoryId("episode")`.
  Итог: состояние живёт во временном SQLite и теряется при перезапуске; траектория
  захардкожена (все диалоги) — нужна правка для многопользовательского режима.
- `appa-runtime/src/api/mod.rs:2235` — `Runtime::open(config, db: PathBuf, modules)`:
  `db` — это eventlog SQLite; передача постоянного пути даёт переживание рестарта
  (детерминированный replay).
- `appa-eventlog/src/sqlite.rs:52-54` — схема keyed per trajectory `PRIMARY KEY (root, seq)`,
  где `root` = `TrajectoryId`; значит **один** SQLite-файл (или файл на диалог) штатно
  хранит множество траекторий и переживает перезапуск через replay `log(root)`.

**Рекомендуемый способ (минимальная правка OpenAPPA, вариант C):**
1. Расширить `appa-agent-python`: конструктору `Session` добавить `store_path` (постоянный
   каталог/файл) и `trajectory_id` (стабильный id = `conversation_id`, через валидацию
   `TrajectoryId::new`) вместо `tempfile::tempdir()`/`"episode"`.
2. В Python-обёртке `TaintGate`: хранилище на диске (volume контейнера, например
   `appa-state:/var/lib/appa`), ключ диалога = `conversation_id`; при рестарте `Session`
   открывает тот же SQLite → eventlog replay восстанавливает метку траектории.
3. Многопользовательская изоляция: каждая траектория уже индексируется по `root`; при
   общем SQLite — изоляция по `TrajectoryId`, при файле на диалог — изоляция средствами ФС.
   Привязка «диалог → траектория» остаётся в памяти/БД банка (тот же `conversation_id`).

**Альтернативы:**
- Sidecar `appa serve` + `appa-eventlog` (SQLite/Postgres) + добавление wire-адаптера
  `python`/`native` (больше Rust-работы, сетевой hop, но готовый daemon/config/replay CLI).
- PostgreSQL-хранилище по образцу `summary.md` (Archestra `@archestra/openappa-rs` +
  `openappa_events`/`openappa_policy_files` + advisory lock на «семью» траекторий) — для
  multi-replica/транзакционной согласованности (P2).
- **Консервативная миграция**: диалоги, открытые до включения персистентности (без записи
  `TrajectoryOpened`), должны стартовать с консервативной меткой (OpenAPPA уже сжигает
  approvals при смене ревизии политики), либо предлагать `/new`.

**Статус:** предложение (реализация отдельным шагом, требуется правка OpenAPPA и пересборка
колеса).

## 6. Ограничения текущей реализации и следующие шаги

Ограничения (не скрываю):
1. **`/v1/chat` E2E не пройден** из-за пустого `EMBEDDING_API_KEY` в окружении (503 памяти) —
   это дефект стенда, не интеграции; до прогона полного сценария требуется задать
   embedding-провайдер (или локальный stub).
2. **Ingress в E2E синтетический** (реальный движок/gate/АБС, но не реальный DDG/память);
   search/memory/travel ingress покрыты юнит-тестами на реальном движке.
3. **Состояние taint в памяти процесса** (сброс при рестарте) — см. §5, требуется правка
   `appa-agent-python` (store_path + trajectory_id).
4. **Audience-измерение не используется** (только Trust), привязка к `customer_id` — P2.
5. `enforce` без колеса теперь fail-closed (исправлено), но это блокирует **все** gated
   вызовы при деградации — для продуктового режима нужен метрический алерт «engine unavailable».
6. Диагностический endpoint существуюет только в isolated-образе (`APPA_TAINT_E2E_HARNESS=1`),
   в основном образе отвечает 404.

Следующие шаги (по приоритету):
- P1.1: правка `appa-agent-python` (persistent `store_path` + `trajectory_id`) + пересборка
  колеса + volume `appa-state` в `docker-compose.appa.yml` + тест «рестарт контейнера →
  taint сохранился».
- P1.2: локальный embedding stub (или ключ) для прогона полного `/v1/chat` E2E
  (реальный ingress search/memory → блокировка перевода).
- P1.3: egress/metadata: gate на `travel.plan` уже есть; добавить контроль получателя
  (`$recipient`) и DLP финального текста ответа.
- P2: PostgreSQL-eventlog + метрики (`openappa_taint_decisions_total{decision,gap}`),
  CI-прогон `tests/test_appa_taint.py` и `openappa-abl/e2e-gate.py` на каждом PR.
